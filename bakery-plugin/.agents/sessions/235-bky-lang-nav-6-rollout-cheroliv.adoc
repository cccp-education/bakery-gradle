== Constats d'audit

. Le site est un **build Gradle autonome** (aucune dépendance bakery) — le
  rollout ne peut pas « consommer la tâche `injectLangSwitch` de bakery »
  directement (layout différent : `jbake/i18n/{lang}/templates` vs le
  `{site}/{lang}/templates` attendu par `InjectLangSwitchTask` de bakery).
. La chaîne `com.cheroliv.i18n` (`LangSwitchLink` → `LangSwitchMenuRenderer` →
  `LangSwitchSiteApplier` → `InjectLangSwitchMain`) **dupliquait** la règle —
  **split-brain** exactement comme décrit par D5 du cadrage S-228.

  copie (le site garde sa chaîne d'injection, mais la *résolution* passe par une
  règle unique alignée sur la spec bakery).

== Dette découverte — null-safety de la règle de référence bakery

CAUTION: `bakery.langswitch.LangSwitchPath.thymeleafHref()` porte le **même bug
latent** que celui corrigé côté site : l'expression self-link
`${content.uri.substring(content.uri.lastIndexOf('/') + 1)}` n'est **pas
null-safe**, or `content.uri` est null sur les pages synthétiques. Le modèle
bakery `src/main/resources/site/templates/archive.thyme` rend `menu.thyme` —
un site scaffoldé par `generateSite` qui bake sa page `archive` **échouerait**
avec le même NPE.

*Preuve* : le bug a été reproduit côté site (test RED `a synthetic page with no
content uri degrades to the language index` → `NullPointerException: target is
null for method lastIndexOf`). La règle site a été corrigée ; la règle bakery ne
l'est pas.
*Impact* : latent pour les sites scaffoldés (aucun FT bakery ne bake l'archive
avec un switcher injecté — d'où le silence).
*Correctif attendu* : aligner `bakery.langswitch.LangSwitchPath.thymeleafHref`
(+ `thymeleafEachHref` du modèle) sur la forme null-safe du site, redémarrer les
vecteurs, et couvrir par un FT qui bake l'archive. **Hors périmètre NAV-6** (le
cœur bakery est clos S-234) — à traiter en session dédiée si un site scaffoldé
rencontre le défaut.
