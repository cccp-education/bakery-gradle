== Livré (2) — bug d'idempotence découvert par dogfooding : `LangSwitcherContainerMask`

Le dogfooding (chaîne `materializeTemplates` → `injectLangSwitch` → re-materialize)
a révélé un **défaut réel** : après injection, le `menu.thyme` de référence porte
le fragment généré ; une seconde materialisation le **keye** (labels de langues →
`menu.9`, `menu.10` absents du bundle gelé) → toutes clés non résolues, la tâche
n'écrit **rien** (variant périmé, Loi de l'Économie d'Encre violée).

* `LangSwitcherContainerMask.strip` (objet pur) : retire le corps généré du
  `lang-switcher-container` (garde la div vide, que `injectLangSwitch` re-remplit).
  No-op strict si conteneur absent/vide, idempotent.
* `I18nMigrationService.extractHardcodedText(content, baseName)` : surcharge
  string pour keyer un template déjà strippé (key space inchangé).
* `MaterializeTemplatesTask.keyTemplate` : strip avant keyage.
* `LangSwitcherContainerMaskTest` : 6 UT (strip, conteneur vide/absent no-op,
  idempotence, intégration keyer — les labels générés ne deviennent jamais clés).
* **Preuve dogfooding** : la séquence qui échouait passe → 0 clé non résolue,
  3e run strict no-op (`0 templates matérialisés`).

== Frontière / non livré (session dédiée)

Le **rollout site complet** (i18n EN + wiring CI + bake variantes) reste un
chantier cross-borough : les sites sont des consommateurs `site.yml` purs
