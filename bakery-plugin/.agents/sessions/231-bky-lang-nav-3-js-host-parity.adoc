== Livré — BKY-LANG-NAV-3

=== 1. `LangSwitchClientParity` — garde pure (DDD)

Domaine pur (chaînes → verdict, zéro I/O). Trois vérifications sur le **même
contenu byte** :

. le module existe dans les **deux** arbres (`maquette/js/` et `assets/js/`) ;
. les deux copies sont **byte-identiques** (pas de drift — pattern
   `bakery.i18n.js.I18nClientPropagation`, décision S-039) ;
. la **surface de contrat** est exposée : le résolveur pur `resolveLangPath`
   **et** l'adaptateur DOM `attachLangSwitch`. La présence seule ne suffit pas.

[source,kotlin]
----
data class Violation(kind, detail)   // missing-module | drifted-module
data class Report(violations)        //  | missing-resolver | missing-adapter
fun verify(maquetteModule: String?, publicationModule: String?): Report
----

=== 2. `lang-switch.js` — l'hôte JS (port fidèle de la règle)

Module navigateur JS plain (zéro build step, UMD-style) : `resolveLangPath(...)`
est le frère JS de `LangSwitchPath.resolveSamePage` (NAV-1) et rejoue **les
mêmes 14 vecteurs partagés**. Division du travail (D2) :

* **mode `tree`** — le serveur a déjà émis le `th:href` exact (NAV-2) ; l'adaptateur
  réécrit les liens `data-lang` page-aware au load et marque la langue active
  (persistance/active). Pas de FOUC, no-JS dégradé propre.
* **mode `dictionary`** — pas d'arbre par langue (talaria) ; l'adaptateur relocalise
  **en place** (`preventDefault`), ne navigue jamais.
* `bootstrap()` auto-câble sur `DOMContentLoaded` (mode/langue déclarés par la page
  via `<html data-lang-switch lang>`), délègue à `TALARIA.I18N.setLang` si présent.

Module copié **byte-identique** dans `maquette/js/` et `site/assets/js/`.

=== 3. Preuve anti split-brain D3 (mêmes vecteurs, deux hôtes)

* **node** (`lang-switch.test.mjs`, 7 tests) : rejoue **chaque** vecteur du
  JSON partagé contre le résolveur JS — la même fixture que
  `LangSwitchPathVectorsTest` côté Kotlin. Une divergence fait rougir un côté.
  Double DOM-free (pas de jsdom) : `fakeElement`/`fakeDocument` + bus de clic.
  Couvre : self/no-op, dégradation cible absente, réécriture page-aware de
  chaque `data-lang`, jamais `en/index.html` en dur, relocalisation dictionnaire.

=== 4. Garde de parité sur les ressources réellement embarquées

`LangSwitchClientParityTest$ShippedResources` : lit le module depuis les **deux**
trees du classpath (`maquette/js/` + `site/assets/js/`) et vérifie présence +
byte-identité + surface de contrat. Le vrai risque D6 est une divergence entre
la ressource de dev et la copie publiée.

=== 5. Functional Oven — un site scaffoldé naît conforme (D7)

`LangSwitchScaffoldFunctionalTest` (TestKit réel) : `generateSite` copie les deux
arbres verbatim → le module existe des deux côtés, byte-identique, avec sa surface
de contrat. Un site neuf n'est plus « né buggé » (constat S-228).

=== 6. Infrastructure — test node dans Gradle + CI

* `nodeTest` (tâche `Exec`, groupe `verification`) : `node --test` sur
  `src/test/node/*.test.mjs`, inputs sur les deux trees + la fixture partagée,
  `download = false` (binaire système, pattern talaria).
* `check.dependsOn(nodeTest)` — le JS est testé par la gate standard.
* CI `test.yml` : `actions/setup-node@v4` (node 22) avant `./gradlew build`.
