== Contexte

Mission A du `PROMPT_REPRISE` S-245. Le PROMPT_REPRISE S-243/244 documentait une
dette cross-borough : `koverThresholdCheck` (conventions-plugin `0.0.4`) lit un
**chemin XML hardcodé** `build/reports/kover/xml/report.xml`, alors que kover
`0.9.8` écrit `build/reports/kover/report.xml`. Bakery était le **seul
consommateur** de la convention kover — le workaround local (S-243 V7) masquait
le bug, mais toute nouvelle convention kover serait fausse.

Les sessions précédentes (S-243 V7, S-244) avaient explicitement classé la
« correction racine conventions » **hors périmètre**. Le pilote a choisi la
mission A (« A ») : corriger en amont, bump, propager, retirer le workaround.

== Constat de cadrage (vérifié dans les sources)

* `KoverConventionsPlugin.kt:69-72` (0.0.4) lit
  `project.layout.buildDirectory.file("reports/kover/xml/report.xml")`.
* le plugin kover `0.9.8` écrit par défaut
  `reports/kover/report${variant}.xml` (sources `kotlinx/kover/.../Paths.kt:30` —
  `xmlReportPath`), soit `reports/kover/report.xml` pour le variant total.
* **Découverte annexe** (bug latent distinct, non corrigé — voir backlog) : le
  helper `invokeMethod(…, "currentProject")` ne matche jamais le getter Java
  `getCurrentProject()` → `configureKover` (includedSourceSets / onCheck) est
  **silencieusement no-op**. C'est pourquoi bakery devait tout configurer
  lui-même. Hors périmètre : l'intention exacte de ce code mort est ambiguë
  (`includedSourceSets = {main, functionalTest}` exclurait `e2eTest` de la
  couverture bakery → changement de sémantique du seuil).

== Le fix (2 baby-steps DDD/TDD/BDD)

=== Baby-step 1 — concept pur `KoverCoverage` (DDD/TDD)

`build.KoverCoverage` (nouvel objet pur, zéro Gradle) : `summarize(xml): Summary`
(missed/covered/percent) + `meetsThreshold(xml, threshold)`. Le `Summary`
encapsule la sémantique **invariante sous la hiérarchie** : les compteurs
`INSTRUCTION` sont répétés à chaque niveau (parent = somme des enfants), donc
sommer tous les compteurs donne le même ratio que le compteur racine.

`KoverCoverageTest` : **6 UT** (agrégation, ratio, rapport vide sans division,
seuil inclusif à la borne, sous-seuil, ignore les compteurs non-INSTRUCTION).
RED → GREEN simple (nouveau type, `Unresolved reference` au premier jet).

=== Baby-step 2 — résolution du vrai chemin (TDD)

`KoverConventionsPlugin.resolveXmlReportFile(project)` : lit la propriété
**réelle** `kover.reports.total.xml.xmlFile` (source de vérité — respecte un
`xmlFile` surchargé par le consommateur, immunise contre le drift de chemin),
fallback sur le défaut kover `0.9.8`. Le `doLast` consomme `KoverCoverage`.

`KoverThresholdCheckFunctionalTest` (TestKit, **RED prouvé**) : 2 FT — défaut
kover + chemin custom. RED initial = `Kover report not found. Run
'koverXmlReport' first.` (chemin hardcodé inexistant), puis GREEN après fix.

=== Baby-step 3 — BDD Cucumber

`kover-threshold-check.feature` (3 scénarios) + `KoverThresholdCheckSteps`
(TestKit réel) : succès sur défaut, chemin custom respecté, échec si couverture
sous le seuil. **RED prouvé par revert ciblé** de la fonction (2/3 scénarios
échouent avec le chemin hardcodé) → GREEN (3/3).

== Leçons

. *Un workaround local masque un bug producteur* : la dette était connue
  (S-243 V7) mais classée « hors périmètre » deux fois. Le fix racine est
  petit (2 baby-steps) et supprime définitivement le workaround.
. *Lire la propriété configurée, jamais le chemin supposé* : kover expose
  `reports.total.xml.xmlFile` — le fix est robuste à toute surcharge, là où le
  chemin hardcodé était fragile.
. *La hiérarchie XML est invariante en ratio* : sommer tous les compteurs
  `INSTRUCTION` est équivalent au compteur racine (parent = somme des enfants).
. *Un bug latent en cache un autre* : `configureKover` (réflexion
  `currentProject` vs `getCurrentProject`) est no-op depuis toujours — découvert
  en lisant le producteur, documenté au backlog, **non corrigé** (sémantique
  ambiguë, hors périmètre A).
