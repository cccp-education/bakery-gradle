== 4. Pourquoi l'adoption est bloquée (CI `43680724558` rouge)

* `Unit Tests` : `ktlintTestSourceSetCheck` — 2 fonctions multi-paramètres de la
  garde à reformater (corrigeable).
* `BDD · i18n-mass-pipeline` : `Translation marker [lang] is present in body`
  **échoue** — le corps du fichier `en/0115_…adoc` reste **le français
  source** : la traduction est rejetée avant écriture.

Cause racine mesurée : **les tags de publication JitPack ne pointent pas sur le
commit de la release Central du même numéro**.

[cols="2,3,3", options="header"]
|===
| Dépôt | Tag JitPack | Release Central du même numéro
| `document-gradle` | `v0.0.30` = `7cdff0e` (2026-11-09) | 0.0.30 publié 2026-11-02
| `codebase-gradle` | `v0.0.18` = `4e2343b` (2026-11-09) | 0.0.18 publié 2026-10-14
| `graphify-gradle` | `v0.0.5` = `be90af6` (2026-11-09) | 0.0.5 publié 2026-09-17
| `plantuml-gradle` | `v0.0.16` = `30dbfdc` (2026-11-09) | 0.0.16 publié 2026-11-02
|===

Le tag `v0.0.30` de `document` contient **DOC-OUT-2** (`a75e509`, 2026-11-04,
postérieur à la release du 2026-11-02) : le JAR JitPack porte
`document.translation.TranslationOutputIntegrity` (absent du JAR Central). Ce
garde structurel rejette le faux traducteur gelé de bakery (`"[en] $source"`),
la traduction échoue et le fichier source est conservé → marqueur absent.
S-273 avait déjà documenté la même dérive pour `plantuml v0.0.16`
(garde de langue `PLT-OUT-3`).

Conséquence : adopter le catalogue relabellé **met à niveau silencieusement
tous les plugins cross-borough** vers du code non testé au numéro de version
annoncé. Ce n'est pas un simple bump de pin.
