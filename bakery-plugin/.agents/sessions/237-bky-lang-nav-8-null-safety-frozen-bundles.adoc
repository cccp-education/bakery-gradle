== Contexte

Reprise bakery à la demande pilote (hook d'ouverture standard), méthodologie
baby-step DDD/TDD/BDD (unit → functional → cucumber), commit/push autorisés en
clôture. Mission = **BKY-LANG-NAV-8** (phase site cccp.education / magic-stick,
i18n à créer).

**Challenge pilote décisif** : « tu ne peux pas déplacer ce qui a déjà été traduit
par l'alignement sur l'infra bakery/cheroliv/talaria, en ayant recours à
l'économie d'encre ? » — vérification faite, **oui**. Le gisement existe :

* Les golden masters `i18n-fixtures/{cccp-education,magic-stick}/post-migration/templates/*`
  sont **byte-identiques** aux templates réels des deux sites (11/11 et 12/12 vérifiés).
* Leurs `#{key}` sont couverts **100 %** par `translations_en.properties` gelés
  (0 clé manquante : 68 clés cccp, 44 magic).
* Le contenu marketing de l'**accueil** vit dans le chrome (`index.N`) → l'accueil
  EN est **entièrement gelé**.

**Maillon manquant** : `jbake-core:2.7.0` installe **aucun MessageResolver** → un
template `#{key}` n'est pas déployable (c'est pourquoi cheroliv déploie en
*full-template swap*). Il fallait la brique déterministe « bundle gelé → template
littéral résolu ».

== Livré (1) — null-safety du cœur (pré-requis bloquant)

Constat S-235 (`NAV-6`, dette) confirmé et soldé **côté bakery** :
`bakery.langswitch.LangSwitchPath.thymeleafHref()` + `thymeleafEachHref()`
embarquaient le **même bug** que cheroliv a corrigé site-side —
`content.uri.substring(content.uri.lastIndexOf('/') + 1)` n'est pas null-safe, or
`content.uri` est **null** sur les pages synthétiques (`archive.thyme`,
`tags.thyme`, masterindex) qui rendent `menu.thyme`. Un site scaffoldé qui bake son
archive **échouait au NPE**. Sans ce fix, injecter le sélecteur dans cccp/magic
cassait le bake de l'archive.

* Baby-step TDD strict : nouveau `LangSwitchPathNullSafetyTest` (6 UT) évalué au
  `TemplateEngine` réel → **RED prouvé** (6/6 FAILED, `NullPointerException:
  target is null for lastIndexOf`) → GREEN.
* Correctif : ternaire explicite `content.uri != null` (Thymeleaf 3.0.14 OGNL
  **n'accepte pas** l'opérateur Elvis `?:`), dégradation vers l'index de langue
  (D8). **Byte-identique au correctif cheroliv prouvé** (S-235) — alignement D3.
* Modèle ex-nihilo (`site-basic/templates/menu.thyme`, `site/templates/menu.thyme`)
  mis à jour (pinné byte-à-byte contre `thymeleafEachHref`).
* REFACTOR tests : 5 fichiers épinglaient l'ancienne forme buguée + steps BDD
  (`LangSwitchSteps`, `I18nDeployEndToEndSteps`) raffinés : un `index.html` n'est
  légitime **que** dans la branche gardée (`content.uri != null`) — jamais un href
  page-blind. Nouvel invariant explicite (pas de faux vert).

== Livré (2) — `MessageBundleResolver` (pont déterministe, zéro LLM)

`bakery.i18n.MessageBundleResolver` — objet pur : substitue chaque `#{key}` par sa
valeur de bundle, préserve le tag/attribut/expression, **rapporte** les clés non
résolues (jamais un template corrompu). Idempotent (template déjà résolu = no-op).

* 7 UT (`MessageBundleResolverTest`) RED → GREEN.
* `FrozenBundleReuseIntegrationTest` (2 tests) **prouve sur les vrais golden
  masters** : 0 clé non résolue, homepage EN matérialisée (cccp : « Common Content
  Creator Proletarian », « Discover the plugins » ; magic : « Standardized
  portable environment… », « A/B Architecture »).

== Livré (3) — `materializeTemplates` (tâche Gradle, zéro LLM)

`bakery.i18n.MaterializeTemplatesTask` : matérialise `i18n/{lang}/templates/`
déployable depuis un bundle gelé.
1. keyage des templates de référence (extraction `extractHardcodedText`, clé
   space identique au golden master) ;
2. résolution par `MessageBundleResolver` contre le bundle gelé.
Langue sans bundle = **skippée, jamais inventée** (D8). Bundle complet = strict
no-op au 2e run. Enregistrée groupe `transform` (`registerMaterializeTemplatesTask`).

* FT `MaterializeTemplatesFunctionalTest` (5) RED → GREEN, dont :
  * arbre EN matérialisé sans aucun LLM (littéral, 0 `#{` résiduel) ;
  * 2e run strict no-op ;
  * langue sans bundle skippée ;
  * **UTF-8** : bug attrapé par le TDD (`Properties.load(InputStream)` lit en
    ISO-8859-1 → `→` devient `â†'`), corrigé `load(Reader, UTF-8)`.

== Périmètre restant (NAV-8 rollout site — session dédiée)

Le rollout site réel n'est **pas** exécuté cette session. Constats de périmètre :
* Les deux sites et leurs golden masters **n'ont pas de `lang-switcher-container`**
  (marqueur requis par `injectLangSwitch`) — le sélecteur est à intégrer dans leurs
  `menu.thyme`.
* `InjectLangSwitchTask.resolveMenuThyme` résout `site/{lang}/templates` alors que
  l'i18n vit sous `i18n/{lang}/templates` — petit delta de layout à traiter.
* cccp/magic n'ont **pas** de build Gradle (consommateurs `site.yml` purs via
  runner-gradle N3) : le wiring `materializeTemplates` + `injectLangSwitch` +
  bake des variantes + CI (`deploy-i18n-site.yml`) est un chantier cross-borough.
