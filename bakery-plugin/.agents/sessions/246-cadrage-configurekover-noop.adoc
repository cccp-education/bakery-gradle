== Constat de cadrage (sources vérifiées)

`conventions-plugin/src/main/kotlin/build/KoverConventionsPlugin.kt` (0.0.5) :

* `configureKover(project)` (lignes 27-62) atteint l'extension kover par
  **réflexion** via `invokeMethod(kover, koverClass, "currentProject")`.
* Or l'API kover `0.9.8` expose **deux** méthodes homonymes
  (`javap` sur `KoverProjectExtension`) :
  ** `currentProject(Action<KoverCurrentProjectVariantsConfig>)` — l'action, 1 param ;**
  ** `getCurrentProject(): KoverCurrentProjectVariantsConfig` — le getter, 0 param.**
* `invokeMethod(…, "currentProject", vararg args)` cherche une méthode nommée
  `currentProject` de `parameterCount == 0` → **ne trouve jamais** `getCurrentProject()`
  (nom JVM différent). Retour `null` → **tout le bloc est silencieusement sauté**.
* **Conséquence** : depuis toujours (le bloc est né dans `996ddae`, CNV-12),
  `includedSourceSets = {main, functionalTest}` et `onCheck = true` (html + xml)
  **ne sont jamais posés**. C'est pourquoi bakery devait configurer kover lui-même
  et pourquoi le workaround S-243 V7 était nécessaire.

=== Intention attendue par le code mort

* `includedSourceSets.addAll("main", "functionalTest")` — les sources mesurées
  sont `main` + `functionalTest`. **`e2eTest` et `test` seraient exclus** de la
  couverture. Les tests (`test`) ne sont jamais comptés dans kover de toute façon ;
  l'exclusion réelle porte sur `e2eTest` (Playwright, non exécuté par `check`).
* `onCheck = true` (html + xml) sur le variant `total` — les rapports s'attachent à
  `check`.

=== Périmètre — un bug latent en cachait un autre

Le chemin XML (bug corrigé S-245/0.0.5) était **orthogonal** : `resolveXmlReportFile`
lit la propriété réelle, indépendamment de `configureKover`. Le workaround bakery
retiré, `koverThresholdCheck` est VERT (89,20 %). Le no-op restant est **distinct**.

== Question de décision (à trancher en S-247 avant le premier baby-step)

Trois options, avec impact sur le seuil de couverture bakery (85 %) :

. **Option A — corriger en typé `KoverProjectExtension`** (`kover.currentProject {
  sources { includedSourceSets.addAll("main","functionalTest") } ; reports { total {
  html { onCheck.set(true) } ; xml { onCheck.set(true) } } }`) : fidèle au code mort,
  mais **restreint la couverture à main+functionalTest** → `e2eTest` exclu (déjà
  non exécuté par `check`) → le seuil peut **changer**. Bump `0.0.6` + propagation.
. **Option B — ne poser que `onCheck`** (laisser `includedSourceSets` au défaut
  kover = tous les source sets) : supprime le no-op, `onCheck` devient effectif,
  couverture bakery **inchangée** (89,20 %). Bump `0.0.6` + propagation.
. **Option C — supprimer `configureKover`** (code mort, zéro intention utile) :
  plus honnête que le patch, zéro changement de comportement. Bump `0.0.6`.

*Recommandation* : **B** (le plus proche de l'intention `onCheck` sans changer la
sémantique de couverture du seul consommateur), sauf si le pilote veut aligner
sur la lettre du code mort (A).
