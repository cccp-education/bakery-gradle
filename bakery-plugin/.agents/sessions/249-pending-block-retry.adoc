= Session 249 — BKY-PENDING-RETRY : le delta fichier rouvre le retry d'un bloc PENDING

_Date_ : 2026-10-06
_Borough_ : bakery-gradle (N2) + cross-borough document-gradle
_Type_ : fix cross-borough (domaine pur + câblage tâche + FT), baby-step DDD/TDD/BDD

== Mission d'ouverture

Décision pilote (S-063 cheroliv.com) : le fix cross-borough `document-gradle`
(DOC-TRANSLATE-RESILIENCE, fixé à S-280) traite le **grain bloc** — un échec LLM
n'est plus gelé `TRANSLATED`. Mais le **grain fichier** de bakery
(`MigrateContentI18nTask` → `I18nDeltaApplier`) préserve tout fichier cible dont
la source est byte-identique : même un bloc correctement marqué `PENDING` ne
serait **jamais ré-entré**. Le fix doit être **apparié**.

== Audit mesuré

* `bakery.i18n.MigrateContentI18nTask.executeContentMigration` : calcule
  `applicationResult = I18nDeltaApplier(delta, existingTargetFiles).apply()`,
  puis `filesToTranslate = applicationResult.toTranslate.paths`.
* `I18nDeltaApplier` : un fichier non modifié au niveau fichier **et** existant
  dans la cible va dans `toPreserve` → jamais retraduit.
* Les checksums de blocs (`loadBlockChecksums`, `.bakery-block-checksums/<rel>.checksums`)
  portent déjà le statut `PENDING`/`TRANSLATED` (document-gradle `BlockChecksumEntry`).

Conclusion : bakery doit **re-scheduler** les fichiers dont les checksums de
blocs contiennent un `PENDING`.

Gates locaux (Local = Build, Tests = CI) : `compileKotlin`/`compileTestKotlin`
VERT, `assemble` + `validatePlugins` VERT, `ktlintCheck` VERT. **Aucun test local**.

**Preuve CI** : run CI bakery `Test` **37443100752** (commit `68d776c5`) →
**success** ; `Publish website` **37443100696** → success.

**Incident CI (2 itérations)** : (1) le nouveau `PendingBlockRetry` (et le
`TemplateStructureGuard` S-250) violaient ktlint (`no-empty-first-line-in-class-body`,
`multiline-expression-wrapping`, `trailing-comma-on-call-site`,
`blank-line-before-declaration`) → CI rouge **avant tout test** ; corrigé
(session formatage). (2) Le FT de convergence end-to-end échouait car la CI bakery
résout `document-plugin 0.0.19` **depuis Central** — version antérieure au fix
bloc `PENDING` (0.0.20 non publié). Le FT a été rendu **auto-portant** : il sème
un bloc `PENDING` directement dans le fichier de checksums (format persisté par
document-gradle) et asserte que le fichier byte-inchangé est re-traduit — l'assertion
tient quelque soit la version résolue depuis Central (la convergence de bout en
bout nécessite la propagation 0.0.20/0.0.23).

== Décisions

[cols="1,5"]
|===
| # | Décision

| D1
| **Le grain fichier rouvre le retry du grain bloc.** `bakery.i18n.PendingBlockRetry.filesWithPendingBlocks`
retourne les fichiers cibles dont les checksums de blocs contiennent un `PENDING` ;
`MigrateContentI18nTask` les **retire de `toPreserve`** et **ajoute à `toTranslate`**.

| D2
| **Domaine pur testable.** `PendingBlockRetry` prend un lecteur de checksums
injecté (`(String) -> Map<String, BlockChecksumEntry>`), donc testable sans
Gradle, sans fichier, sans LLM. 4 UT.

| D3
| **Aucun checksum absent n'est retenté.** Un fichier sans fichier de checksums
(`emptyMap`) n'a pas de bloc `PENDING` : il est laissé au delta fichier
normal (nouveau fichier → déjà traduit).

| D4
| **Preuve de convergence end-to-end.** FT `PendingBlockRetryConvergence` :
run 1 (LLM échoue sur un paragraphe) → bloc `PENDING` persisté ; run 2 (source
inchangée, LLM récupéré) → bloc `TRANSLATED`, plus aucun `PENDING`.

| D5
| **Baby-step DDD/TDD strict** : unit (domaine) → functional (tâche réelle,
2 runs). Zéro affaiblissement de garde, zéro contrat N0 touché.
|===

=== Options écartées

* **Ne rien faire côté bakery** — le `PENDING` block-level de document-gradle
  serait inerte (gelé au gate fichier).
* **Forcer la re-traduction de tout fichier présent** — contredit l'Économie
  d'Encre et l'idempotence (S-233 « second run unchanged translates nothing »).
* **Marquer le fichier en erreur** — un échec LLM transitoire ne doit pas
  bloquer 111 articles ; le retry delta est la voie.

== Implémentation (baby-step)

. **US-1 — `PendingBlockRetry` (domaine pur)**
   * `filesWithPendingBlocks(existingTargetFiles, blockChecksumsOf)` : un
     fichier est retenté ssi au moins un de ses blocs est `PENDING`.
   * Tests unit : `PendingBlockRetryTest` (4 tests).

. **US-2 — câblage `MigrateContentI18nTask`**
   * `pendingRetry = PendingBlockRetry.filesWithPendingBlocks(existingTargetFiles) { loadBlockChecksums(langDir, it) }`
   * `filesToTranslate = applicationResult.toTranslate.paths + pendingRetry`
   * log enrichi (`dont N retentés PENDING`).

. **US-3 — FT `PendingBlockRetryConvergence`**
   * `MigrateContentI18nDeltaFunctionalTest` : nested `ControllableTranslationService`
     (échec conditionnel) + 2 runs, source inchangée, assertion `PENDING`→`TRANSLATED`.
