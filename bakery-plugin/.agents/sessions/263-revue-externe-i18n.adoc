= Session 263 — Revue externe i18n (qualité des 21 langues + boroughs engagés)

== Contexte

Demande pilote : porter un avis mesuré sur la qualité des traductions de
`office/sites/cheroliv.com` (prose + diagrammes) et sur les boroughs engagés dans
le processus d'internationalisation. Session **documentaire** : aucun code bakery
modifié, aucun test modifié, aucune publication.

Mission de la session 263 initialement proposée par S-262 (`G-4` audit unifié,
`G-5` économie d'encre, release `0.0.29`) : **non consommée**, reportée S-264.

== Périmètre audité

* Corpus local `office/sites/cheroliv.com` (lecture seule) : 184 fichiers FR
  (dont 72 drafts exclus), 112 articles publiés × 21 langues = ~2 350 variantes.
* Site déployé (`https://cheroliv.com`) : pages `/en/`, `/ar/`, `/ja/`, `/th/`,
  `/sr/`, et articles 0108/0119/0123/0125/0126.
* Chaîne de production lue : bakery (bake, `migrateContentI18n`, `i18n/variant`,
  `i18n/rtl`, `i18n/js`), document (pivot AST), plantuml (`boundary` :
  `PlantumlTermShield`, `TextClassifier`, `PlantumlSyntaxValidatorAdapter`),
  runner (orchestration), MEMPHIS (`i18n-contracts`), codebase (hub LLM).

== Avis par borough (synthèse)

* *MEMPHIS (N0)* — bon socle (`LanguageCatalog` 22 langues, `TranslationService`) ;
  manque le contrat « ce qui ne se traduit jamais » (macros, attributs, specs de
  tableau, fences, identifiants), réimplémenté trois fois.
* *bakery (N2)* — moteur et outillage de variantes solides ; porte les défauts de
  sortie (duplication, tableaux, `toc`, head/SEO) ; gardes au niveau état, pas rendu.
* *document (N2)* — bonne architecture (pivot AST, delta, idempotence) ;
  `TextTranslatableClassifier` trop naïf ; store de blocs autorisant la réinsertion
  multiple.
* *plantuml (N2)* — le meilleur morceau (`PlantumlTermShield`, stratégies, glossaire,
  validateur de syntaxe) ; à transformer en gate bloquant sur le corpus réel.
* *runner (N3)* — orchestration propre, mais `reportConvergence` est un faux vert
  (état du store, pas de l'artefact).
* *codebase (N1)* — aucune validation de sortie LLM (langue cible, refus,
  placeholders) ; `TranslationSafetyWrapper` à faire vivre ici, partagé.

== Décisions

. La revue est un *avis externe daté et non arbitré* — source de constats, jamais
  un cadrage ni un PROMPT_REPRISE.
. Aucun borough nouveau n'est convoqué (review/dashboards hors périmètre, maturité
  insuffisante) ; la couche de vérification reste dans la chaîne existante.
. Chaque défaut retenu devra être re-prouvé RED avant correctif ; le delta
  HEAD ↔ site déployé (S-076 non déployé) doit être re-mesuré.
. Les gates P0 (intégrité structurelle, langue/sentinelle, rendu diagramme) sont
  des *candidats* à arbitrer en S-264 (G-4/G-5).
