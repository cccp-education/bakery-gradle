== Demande pilote

Les dépôts runners (`cheroliv-contact/cheroliv.com`, `talariaschool/talaria-school`,
`cccp-edu/magic-stick`, `cccp-edu/cccp.education`) ne doivent PAS être des sources
de vérité. `office/sites/<site>` reste la seule source. Les runners reçoivent une
copie au `commit`/`push` (miroir dérivé), pour que leurs Actions tournent sous un
autre compte (contournement du blocage billing `cheroliv`).

Décision : **mutualiser dans bakery** plutôt que dupliquer la logique JGit dans
`office`. `pushCiMirror` réutilise la même primitive que `deploySite`.

== Mutualisation

Le geste est identique à `deploySite` :
`registerGitPushTask` → `GitService.pushPages` (copie dans `build/`,
`git init/add/commit`, force-push avec les credentials de `site.yml`).
Seules la source (site source au lieu du bake) et la cible (repo runner) changent.

== Livré

* `SiteConfiguration.pushCiMirror` — même forme que `pushPage`/`pushMaquette`.
  `to` = répertoire scratch under `build/` (défaut `ci-mirror-push`) ; `from`
  ignoré (payload fixe `build/ci-mirror`, comme `deploySite` ignore `pushPage.from`).
* `bakery.CiMirrorPayload` (domaine pur) : copie `office/sites/<site>` sous
  `sites/<site>/` puis l'overlay `.ci-mirror/` à la racine ; exclut `.agents/`,
  `.git/`, `.github/`, `.gradle/`, `.kotlin/`, `.idea/`, `build/`, `.ci-mirror/`,
  `site.yml`, `site.yml.bak*`, `local.properties`, `graph.json`, `*.iml`.
* `DeployTaskRegistrar.registerCiMirrorTask` + wiring `BakeryPlugin`.
* Tests : `CiMirrorPayloadTest` (6 UT), `CiMirrorFunctionalTest` (TestKit + remote
  bare réel), `DeployTaskRegistrarTest` (+1 UT). Functional shard D.
