**Objet** : le cadrage talaria verrouillé S-054

**3** dictionnaires i18n JS. Les 2 premiers (chrome `var DICT`, patch
`TALARIA.I18N.extend`) sont **plats**. Le 3e, `maquette/js/i18n-content.js`
(`TALARIA.I18N.CATALOG`), est **imbriqué** : langues → formations (`fpa`/`cda`)

contrat de delta est explicite :

____
« Par langue : bloc absent = langue entière manquante ; le delta de tâche porte
sur la **présence de langue** et, si le bloc existe, les **champs manquants**. »
____

== Diagnostic RED (faits mesurés)

. *Le catalogue n'est jamais traduit* — `I18nJsDictionary.parse` est plat
  (regex clés **quotées** `"key": "value"`, `I18nJsDictionary.kt:20-23`). Dans
  `i18n-content.js` les clés sont **non quotées** (`title:`, `fpa:`) → `parse()`
  voit les blocs langue mais **0 clé**. Le delta du catalogue est donc
  structurellement toujours vide.
. *Bug latent de propriété* — `I18nClientDelta.languageOwners` retient « le
  premier fichier qui possède le bloc langue ». Or le tri réel de la tâche
  (`walkTopDown().sortedBy { relativePath }`) est alphabétique :
  `i18n-content.js` < `i18n-extra-langs.js` < `i18n.js`. Le **catalogue devient
  donc propriétaire des 22 langues**. KDoc annonçait pourtant « the chrome
  dictionary wins over the patch » — l'intention était inversée. Dormant tant
  que le corpus est complet (plan vide), mais dès qu'une clé chrome `fr` est
  ajoutée elle serait insérée **dans le catalogue imbriqué** (corruption).
. *La tâche ne partitionne pas* — `--i18nClientSource=…/maquette/js` (dossier
  entier, `talaria.school/build.gradle.kts:146`) inclut le catalogue dans le
  flux plat ; il est ignoré pour les clés mais reste éligible à l'ownership et
  au writer.
. *Les tests ne l'attrapent pas* — la fixture `talaria-i18n-client` ne contient
  que chrome + patch ; le catalogue n'apparaît nulle part dans les tests.

== Implémentation

=== US-5a — `I18nJsFormat` + ownership restreint (DDD/TDD)

`bakery.i18n.js.I18nJsFormat` (enum pur `FLAT`/`CATALOG`, `of(source)` sur le
marqueur `TALARIA\.I18N\.CATALOG\s*=`, prédicats `isFlat`/`isCatalogue`). Le
marqueur est **autoritaire** : le catalogue réutilise l'indentation flat et ne
doit jamais être confondu.

`I18nClientDelta.languageOwners` saute désormais les sources `CATALOG` — le
catalogue ne peut plus capter de clé plate.

=== US-5b — `I18nCatalog` (DDD/TDD)

`bakery.i18n.js.I18nCatalog` (object pur) : `languagesOf`, `formationsOf`,
`fieldsOf` (parser imbriqué à indentation paramétrée 4/6/8, scanner
string-aware) et `plan(source, reference, targets): I18nCatalogPlan`.

`I18nCatalogPlan` (data class) : `languages`, `missingLanguages`,
`missingFormations` (langue → formations), `missingFields` (langue → formation
→ champs) + compteurs + `hasGap` + `EMPTY`. Le plan est vide quand la référence
ne possède aucun bloc catalogue (un dictionnaire plat n'a pas de catalogue).

=== US-5c — Câblage tâche (partition + report + garde)

`TranslateI18nClientTask` :
. partitionne les sources `catalogueFiles` / `flatFiles` **avant** la garde de
  format et le delta plat — le catalogue ne passe **jamais** dans le writer plat
  ni dans `I18nClientFormatGuard.verify` ;
. reporte la couverture catalogue (`logCatalogueCoverage`) : lacune → `warn`
  détaillé (langues, formations, champs), complète → `lifecycle` « aucune
  lacune », arbre sans catalogue → silence (Économie d'Encre) ;
. seam `internal fun catalogueCoverage(intention): I18nCatalogPlan` testable
  sans Gradle (pattern S-220 `execute()`).

=== REFACTOR — `I18nJsBlockScanner`

Le scanner balanced-brace string-aware était dupliqué (flat + catalogue).
Extrait en objet `internal` unique consommé par les deux (`matchingBrace`,
`bodyFrom`) — `I18nJsDictionary` et `I18nCatalog` délèguent.

== Décisions

. *Le catalogue est une couverture, pas une écriture plate* — le contrat S-054
   est « présence de langue / champs manquants ». La tâche **reporte** la
   lacune ; la traduction du contenu imbriqué est un chantier distinct
   (elle exigerait un writer imbriqué + validation de structure, hors périmètre).
. *`I18nJsFormat` = source unique de vérité du format* — la classification par
   marqueur explicite remplace toute heuristique d'indentation (le catalogue
   partage l'indentation flat).
. *Défense en profondeur* — la tâche partitionne (`flatFiles`/`catalogueFiles`)
   **et** `languageOwners` saute le catalogue : deux gardes indépendantes. Le
   scénario BDD de capture passe par la partition ; le UT le prouve par
   l'ownership (RED restauré).
. *Report warn, pas silencieux* — une lacune catalogue est un signal de
   couverture, pas une erreur de build : `warn` détaillé sans faire échouer la
   tâche (le verrou de couverture reste côté talaria `I18nCatalogCoverageGuard`).
. *Scanner extrait* — la règle balanced-brace string-aware (valeur `"{0}"`) est
   trop subtile pour être dupliquée ; un seul objet `internal` la porte.
