== Contexte

EPIC BKY-OUTPUT — dernière US restante (44/49 pts, 90%).
`ThemeResolver` (TREE-5, S167) et `OutputConfigResolver` (OUTPUT-2, S172)
existaient séparément. `TreeBakeService.injectTreeConfig()` appelait les deux
indépendamment puis mergeait le thème dans `buildConfigMap`. L'objectif :
faire de `OutputConfigResolver` la source unique de vérité en y injectant
`ThemeResolver`, pour que le thème soit déjà résolu dans l'`OutputConfig`.

== Baby steps

=== DDD — OutputConfigResolver accepte ThemeResolver

`OutputConfigResolver(tree, themeResolver?)` — paramètre optionnel backward-compat.
`effectiveConfig()` : après merge de la chaîne d'ancêtres, si `themeResolver`
est présent, résout le thème via `themeResolver.effectiveTheme(node)` et
l'injecte dans l'`OutputConfig` retourné via `copy(theme = ...)`.

=== DDD — TreeBakeService simplifié

- `ThemeResolver` créé puis passé à `OutputConfigResolver(siteTree, themeResolver)`
- Suppression de `themeResolver.resolveAll()` séparé
- `buildConfigMap(out, meta)` — le paramètre `theme` est retiré, le thème
  est déjà dans `out.theme`
