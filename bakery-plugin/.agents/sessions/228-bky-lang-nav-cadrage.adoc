== Contexte

Reprise bakery à la demande pilote (hook d'ouverture standard). Demande
explicite : ajouter un EPIC pour que, lorsqu'on change de langue en naviguant
sur le site, on arrive sur **la traduction de la page où l'on était**, et non
sur la page d'accueil de la langue demandée. Les 4 sites cibles sont
cheroliv.com, talaria.school, cccp.education et magic-stick.

Session de **cadrage (gouvernance pure)** : audit du bug, arbitrage
architectural avec le pilote, rédaction du doc de cadrage, synchronisation
backlog. Zéro code modifié.

== Audit — le bug est structurel (résolution d'URL, pas JS)

Le résolveur ne connaît que la *langue*, jamais la *page*.

`src/main/kotlin/bakery/langswitch/LangSwitchUrl.kt:23-31` :

[source,kotlin]
----
fun resolve(): String {
    if (isSelfLink()) return "index.html"
    val root = rootpath()
    return if (targetLanguage == defaultLanguage) "${root}index.html"
           else "${root}$targetLanguage/index.html"   // index.html en dur
}
----

`currentPath` désigne le répertoire de langue, pas la page. Le mapping
page→page **existe déjà** sur cheroliv.com mais uniquement côté SEO
(`jbake/templates/header.thyme:8-16`, `hreflang` via `content.uri`) — le patron
à réutiliser.

=== Split-brain

cheroliv.com **copie** la logique (`com.cheroliv.i18n.LangSwitchLink.thymeleafHref()`
+ `LangSwitchMenuRenderer`/`LangSwitchSiteApplier`/`LangSwitchBlockInjector`/
`InjectLangSwitchMain`), avec le même `index.html` en dur → deux sources de
vérité pour la même règle.

émet un href absolu non page-aware → un site scaffoldé naît buggé.

== Décision pilote actée

*S2 + hybride, Thymeleaf conservé.* Discussion d'arbitrage (3 tours) :

- Le pilote préfère **S2** (responsabilité de résolution au JS) — refus de
  confier la décision de navigation à Thymeleaf.
- Correction de prémisse : Thymeleaf sur un générateur statique **ne demande pas
  de serveur** (tâche `bake` déterministe, testée sans serveur aujourd'hui).
  Le bon motif de S2 est l'**uniformité maquette ∪ JBake ∪ cross-site**, pas la
  testabilité.
- Le pilote valide l'**hybride** pour SEO + FOUC et confirme **garder Thymeleaf**
  comme moteur de template.

Division actée :
- **Arbre de pages** → Thymeleaf résout au build (exact, crawlable, no-JS, sans
  FOUC) ; le JS surenchérit (persistance/active), ne réécrit pas le lien exact.
- **Dictionnaire client** → JS résout (Thymeleaf n'a rien à résoudre).
- **Parade anti-split-brain** : **une règle pure, deux hôtes, vecteurs de test
  partagés**.
