:date: 2026-11-03

== Mission

Rendre la recherche du template bakery exploitable sans casser les contrats de
chrome des consommateurs : `PagefindUI` remplaçait le formulaire et faisait perdre
les ancres `keywords`/`searchSubmit` ; les templates pointaient `_pagefind/` alors
que Pagefind 1.6 écrit `pagefind/`.

== Livré

* Domaine pur `bakery.search` : `SearchBundle`, `SearchIndex`/`PagefindEntry`
  (parseur tolérant `include_characters`), `PagefindIndexContract`,
  `BakedLanguages`.
* Adapter JS `search-pagefind.js` headless (formulaire conservé, import paresseux,
  rendu des résultats), copie byte-identique `site/assets/js` ↔ `maquette/js`.
* Templates par défaut : `pagefind/`, formulaire + `#pagefind-results`, 10 bundles
  `messages_*.properties` (`action.search.keywords`/`noResults`), footer headless.
* `validateSearchIndex` : compare l'entrée Pagefind aux langues réellement
  stagées (racine + sous-dossiers `index.html`), échoue si une langue manque ou
  indexe zéro page.
* Tests : `SearchBundleTest`, `PagefindEntryTest`, `PagefindIndexContractTest`,
  `PagefindTemplateWiringTest`, `BakedLanguagesTest`, `search-pagefind.test.mjs`
  (9/9), garde de task dans `SiteManagerTest`.
