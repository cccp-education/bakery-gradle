== Mission

US **BKY-I18N-JS-3** du BACKLOG : task `translateI18nClient` (domaine `bakery.i18n.js`) —
`I18nClientMigrationIntention` + DSL `bakery { i18nClient { ... } }` + CLI +

`LlmServiceTranslationAdapter` → port N0 `contracts.i18n.TranslationService`.

== Bugs attrapés par le TDD

1. **Faux positifs de test (BS-1)** : le `en` du fixture n'était pas « complet »
   (1 clé manquante) — 2 assertions revues, code correct. Le domaine testé
   distingue « complète » et « en du sample ».
2. **Fixtures functional (BS-4)** : interpolation `trimMargin` (`$enBlock`)
   collait le bloc `en` sans indentation attendue → delta 0. Remplacé par
   `buildString` explicite.
3. **Assertion fonctionnelle erronée** : `nav.cart` existe légitimement dans le
   bloc `fr` — assertion affinée sur le bloc `en` (`englishBlock()`).
4. **Step Cucumber regex** : `{string} requests?` n'est pas une expression
   valide (Cucumber compile `{string}` littéralement) → 2 steps explicites
   singulier/pluriel.

== Décisions actées

. **Frontière LLM = socle bakery local** (constat C-1 S-054) : réutilise
   `LlmServiceTranslationAdapter` + port N0 `contracts.i18n.TranslationService`.
   Pas de nouvelle interface. Migration `LlmBuildService` (codebase N1) hors
   périmètre.
. **Propriété des blocs découverte par parsing** (`languageOwners`) au lieu des
   listes hardcodées `CHROME_LANGUAGES`/`PATCH_LANGUAGES` du harness — moins de
   couplage, plus résilient à un nouveau fichier de dictionnaire.
. **Source dirs relatifs au `projectDir`** (layout talaria : `maquette/js` et
   `jbake/assets/js` sont frères, pas sous `bake.srcPath`).
. **Échec LLM = clé conservée absente** : le document reste un JS valide, la
   re-run retentera le delta (économie d'encre préservée).
. **Le catalogue imbriqué** (`i18n-content.js`) n'est pas traité par cette US
   (presence de langue seule, cf. cadrage) — `I18nJsDictionary` ne lit que les
   formes plates.
