== Découverte sécurité — secrets Firebase dans les fixtures (neutralisés)

La resync des fixtures depuis le site réel a introduit la **vraie clé API
Firebase** Firebase + appId Firebase du site cheroliv.com dans les
fixtures trackées git. L'ancienne fixture avait des placeholders
(`REMPLACER_PAR_VOTRE_API_KEY`). Règle workspace : zéro API key committée.

Baby-step TDD :
1. *Neutralisation fixtures* — `apiKey` + `appId` remplacés par placeholders
   dans `i18n-fixtures/cheroliv-com/jbake/templates/footer.thyme` +
   `post-migration/templates/footer.thyme` (grep API key = 0).
2. *TDD RED* — nouveau test auditor `template differing only by injected
   secrets is aligned` : échec attendu (placeholders ≠ vraie clé).
3. *Implémentation* — `FixtureAlignmentAuditor.neutralizeSecrets()` :
   regex `apiKey:\s*"..."` + `appId:\s*"..."` → placeholder canonique avant
   hash. Seule la divergence secrets-only est ignorée, toute autre divergence
   reste rapportée. Auditor 8/8 PASS.
4. *Conséquence* — `RealSiteI18nMigrationIntegrationTest` : la copie du site
   réel (vraie clé) vs golden master (placeholders) → comparaison
   secrets-neutralisée ajoutée dans `assertSnapshotsMatch` (2/2 PASS).

Le site réel garde ses vraies valeurs (production). Les fixtures test et
golden masters portent des placeholders. L'auditor les considère alignées
car seule la valeur injectée diffère.
