== Contexte

Mission A du `PROMPT_REPRISE` S-242 : la garde `FixtureAlignmentAuditor` lit
`office/sites/cheroliv.com` par **chemin absolu en dur** → fragile en CI isolée.
Cause racine récurrente des FLAKY-4 (S-222) et FLAKY-5 (S-241).

L'audit d'ouverture S-243 a mesuré l'ampleur réelle : **la CI GitHub Actions est
rouge sur la totalité des runs disponibles** (`Test` workflow, 200/200 en échec,
remontant à 2026-06-14). Ce n'est donc pas une dette latente ponctuelle mais un
**état de fait permanent** : aucune gate cross-borough ne peut être verte en CI.

V2/V3/V4/V9 sont quatre occurrences du **même anti-pattern** : un test lit une
ressource *hors du dépôt* (site réel `office/`, dépôt voisin `workspace-bom/`,
`site.yml` gitignoré racine) sans seam de résolution ni dégradation propre. Le
patron de sortie existe pourtant déjà dans le dépôt :
`DnsDogfoodTalariaIntegrationTest` et `I18nJsDictionaryTalariaIntegrationTest`
font un `assumeTrue` propre ; `graphify-gradle` (EPIC D5-RACE, S-029) a résolu
V4 pour son équivalent en **injectant la version du catalogue publié** par
Gradle (`systemProperty`) au lieu de lire le voisin.

V9 n'a été **révélé qu'après le push** : la CI mourait auparavant sur V1 puis
bloquait sur V5/V6 ; une fois ces verrous levés, `functionalTest` a atteint le
code et a exposé la lecture du `site.yml` externe.

V5/V6/V7/V8 ne sont **pas** causés par le delta S-243 : ils préexistent sur HEAD
(stash-prouvé), mais étaient **masqués** — V5/V6 par la CI qui mourait en
configuration (V1), V7/V8 par les tâches en amont qui échouaient. Ils ne sont
apparus qu'au fur et à mesure que la chaîne avançait.

== Décision — huit chantiers

=== US-1 — Débloquer la configuration CI (V1)

Bump `.github/workflows/test.yml` `java-version: '24'` → `'25'`, aligné sur
`capsule-gradle` et `document-gradle` (déjà à 25 car consommateurs du même
`conventions-plugin:0.0.4`). Aucun autre changement de workflow.

=== US-2 — Rendre les gardes workspace-aware (V2/V3/V4)

**Principe (DDD)** : extraire un objet pur de résolution de la racine workspace
— source unique de vérité pour les trois tests — avec un **seam injectable**
(propriété système > variable d'environnement > défaut local) et une
**dégradation nullable** (`takeIf { isDirectory }`) consommée par `assumeTrue`.

. **US-2a** — `bakery.workspace.WorkspaceRoot` (test helper, baby-step TDD) :
  `resolve()` avec précédence `-Dbakery.workspaceRoot` > `WORKSPACE_ROOT` >
  défaut `/home/cheroliv/workspace` ; `siteTemplates(siteDirName): File?` et
  `siteJbake(siteDirName): File?` nullables. UT du resolver (présence, absence,
  précédence).
. **US-2b** — câbler `FixtureAlignmentAuditorTest` + `RealSiteI18nMigration
  IntegrationTest` sur le resolver : `require(...)` → `assumeTrue(...)`. **Preuve
  locale du skip** : lancer la suite avec `-Dbakery.workspaceRoot=/nonexistent`
  → les tests **skippent** (pas d'échec), reproduisant la CI isolée sans elle.
. **US-2c** — `BakeryPluginPublicationTest` : remplacer la lecture du voisin par
  une **version injectée par Gradle** (patron graphify D5-RACE) —
  `systemProperty("bakery.publishedCatalog.bakeryVersion", ws.versions.bakery.plugin.get())`
  + `...bomVersion`. Objet pur `bakery.workspace.PublishedCatalogVersion.require`
  (3 UT) : propriété absente/vide → erreur explicite, jamais de vert silencieux.

=== US-3 — Réaligner les scénarios BDD périmés (V5)

Les 4 scénarios testaient une sémantique **révolue** (drift d'évolution
légitime), pas un bug produit :

. **F30** — `de` est devenu une langue **supportée** (BKY-LANG-22, 22 langues via
  `LanguageCatalog`) → le scénario de fallback utilise désormais `xx` (vraiment
  inconnue) ; en-tête de feature réaligné 10 → 22 langues.
. **F34** — l'assertion « dry-run n'a rien modifié » reposait sur l'absence de
  `th:text=` dans `header.thyme`, or le chrome réel de cheroliv porte
  légitimement un `th:text` (titre SEO dynamique) → remplacée par une **empreinte
  avant/après** (`BakeryWorld.snapshotTemplates`), drift-proof.
. **DNS** — le produit **scope** les suppressions aux slots déclarés (BKY-DNS-6
  dogfooding, `DnsDiffTest` le documente) → le scénario d'orphelin utilise
  désormais un slot déclaré ; nouveau scénario « out-of-scope jamais supprimé ».
. **F50** — `document-gradle` **traduit** désormais `:summary:`/`:description:`
  (`FrontmatterStaleDetector` TRANSLATABLE, `DocumentTranslatorTest` le pinne) →
  l'assertion vérifie que l'attribut *et sa traduction* sont présents.

=== US-4 — Assainir les timeouts (V6)

`cucumberTest` et le timeout `Test` global passent de 5 → 15 min (marge sûre).
Un timeout trop court tuait la tâche avant le flush des résultats → comptes
d'échecs non déterministes masquant V5.

=== US-5 — Aligner le chemin du rapport kover (V7)

`kover { reports { total { xml { xmlFile.set(...) } } } }` local : aligne la

bug était donc latent. Le bug racine reste à corriger côté conventions (EPIC

=== US-6 — Baselinage ktlint (V8)

=== US-7 — Dé-coupler les tests du `site.yml` hors repo (V9)

Objet `FuncTestsConstants.SITE_CONFIG_YML` : configuration canonique **in-repo**

== Risques et mitigations

*Risque* : après V1, de nouveaux échecs CI apparaissent en cascade — **réalisé**
(V5→V8). *Parade* : chaque verrou a été diagnostiqué puis traité, la chaîne
complète `build` est verte localement avant le push.

*Risque* : `assumeTrue` masque une vraie régression locale. *Parade* : le seam a
un **défaut = chemin local réel** → en poste de dev, les tests s'exécutent
normalement ; seul un override explicite (CI ou preuve locale) skippe.

*Risque* : le baseline ktlint masque une dette qui ne sera jamais résorbée.
*Parade* : EPIC « ktlint baseline cleanup » à cadrer ; le baseline n'exempte
aucun fichier neuf, la dette ne peut donc que décroître.
