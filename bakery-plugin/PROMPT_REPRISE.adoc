== Contexte de la demande (S-228)

Pilote : « lorsque je change de langue lors de la navigation sur le site, une
fois arrivé dans la langue demandée je dois être sur la traduction de la page
où j'étais, et non pas un retour à la page d'accueil dans la langue demandée. »
4 sites cibles : cheroliv.com, talaria.school, cccp.education, magic-stick.

== Constat (audité S-228)

Le défaut est **structurel** (résolution d'URL, pas JS) :
`src/main/kotlin/bakery/langswitch/LangSwitchUrl.kt:23-31` — `resolve()` jette la
page (`index.html` en dur) ; `currentPath` = répertoire de langue, pas la page.
Le même bug est **copié** sur cheroliv.com (`com.cheroliv.i18n.LangSwitchLink`
+ renderer/applier/injector + `InjectLangSwitchMain`) → **split-brain**.
Le mapping page→page existe déjà côté **SEO** sur cheroliv
(`jbake/templates/header.thyme:8-16`, `hreflang` via `content.uri`).

Sites : cheroliv = bug réel (arbres `jbake/i18n/{lang}/`) ; talaria = marche
déjà (dict client `TALARIA.I18N.setLang`, ne navigue pas) ; cccp + magic-stick =
**aucun i18n** (chantier à créer). Modèle ex-nihilo (`site-basic`/`maquette`)
sans sélecteur → un site neuf naît buggé.

== Décision architecturale actée (P1, ne pas rouvrir)

**S2 + hybride, Thymeleaf conservé.** Une règle pure, deux hôtes, vecteurs de
test partagés :
. **Arbre de pages** → Thymeleaf résout au build (`${content.rootpath + 'en/' + content.uri}`)
   — exact, crawlable, no-JS, sans FOUC ; JS surenchérit (persistance/active),
   ne réécrit pas le lien exact.
. **Dictionnaire client** → JS résout (Thymeleaf n'a rien à résoudre).
. **Parade anti-split-brain** : spec unique + vecteurs partagés. **Supprimer la
   copie cheroliv** (D5).
Détail complet : `.agents/CADRAGE_EPIC_BKY_LANG_NAV.adoc`.
